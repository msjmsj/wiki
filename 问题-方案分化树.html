A. 认知类问题

代码难以理解或修改 —— 影响开发者,与机器运行无关

复杂度

规模复杂度
  • 单个东西太大→拆分单一职责深模块
嵌套复杂度
  • 嵌套太深,逻辑呈箭头型→卫语句拆分

耦合

结构耦合
  • 东西之间的关系乱→分层依赖方向管理外观模式模块只露统一入口
变化耦合
  • 一处变化要改很多地方→信息隐藏
创建耦合
  • 创建对象写死类名,换实现要全局搜 new→工厂依赖注入
通信耦合
  • 一变要通知多方,直接调用缠成网→观察者发布订阅中介者⚠︎

复制

重复
  • 同一个修改要在多处重复→DRY抽象复用YAGNI⚠︎

可扩展性

  • 加新功能必须改老代码→开闭原则多态策略模式查表驱动装饰器中间件模板方法

边界

集成演进
  • 两个接口对不上,又改不了其中一方→适配器

可测试性

  • 全局实例到处被 import,测试难写→显式注入受控单例
  • 业务逻辑和框架 / IO 缠在一起,没法单测→纯函数核心依赖注入

风险

  • 改行为必须改代码发版,上线回滚都疼→特性开关⚠︎
  • 不敢修改,担心破坏现有功能⇢ 另一根源在 C→契约测试

B. 运行类问题

运行结果错误或外部依赖失效 —— 发生在机器层面,与代码组织方式无关

可追溯性

可变性
  • 不知道谁改了数据→不可变单一数据源单向数据流
可审计性
  • 历史丢了,无法审计回放→事件溯源Memento活动日志
  • 用户要求撤销 / 重做→命令模式Memento事件溯源

时序

并发
  • 多线程 / 异步抢同一份数据→不可变消息传递锁纪律
  • 慢响应后到,覆盖了新数据→竞速取消防抖
原子性
  • 执行一半挂了,数据半新半旧→事务补偿动作命令模式定时对账

复制

一致性
  • 有副本:副本与源头不一致→TTL失效优先于更新⚠︎
重复
  • 外部会重复→幂等去重状态机
  • 多实例部署后,定时任务被重复执行并发→分布式锁选主

边界

可靠性
  • 外部会失败→超时重试熔断降级
  • 外部会丢失→确认 ack重投死信队列消费端幂等
集成演进
  • 外部会变化→防腐层Schema 校验代理

资源有限

性能
  • 要实时感知服务端变化,只能高频轮询→服务端推送
  • 一次拉全量数据,又慢又大→游标分页增量同步
  • 太频繁,资源吃紧→节流防抖批处理
  • 太慢→缓存异步并行索引
容量与可用性
  • 存不下 / 怕单点故障→分片副本分治

C. 协作类问题

组织协作与长期演进 —— 多人、长周期项目中出现

归属

  • 多人修改同一文件,合并冲突频繁→Conway一个模块一个 owner

决策流程

  • 方案评审难以达成共识→ADR

边界

集成演进
  • 上下游接口变更互相不知情,联调靠喊→API 契约消费者驱动契约

风险

  • 老代码没人敢动⇢ 另一根源在 A→契约测试可逆设计known-violations 基线
  • 依赖和技术栈越拖越旧,升不动了熵增→依赖保鲜契约测试
  • 老系统想推倒重写→绞杀者模式

熵增

约定执行
  • 新功能不知道放哪,全堆进大文件→架构红线脚手架
  • 新人 / AI 上手就破坏结构→规范文档CI 强制
知识管理
  • 文档写完就过时,没人维护→文档即代码契约测试
  • 核心模块只有一个人懂归属→结对与轮值一个模块一个 ownerADR
  • 忘记当初为什么这么做→ADR

创建型

对象怎么来 —— 把「new 什么、怎么 new」从使用方剥离

选实现
  • 工厂 工厂方法 Factory Method 把实例化推迟到子类 / 集中点,使用方不直接 new ← 创建对象写死类名,换实现要全局搜 new
  • 抽象工厂 创建一族相关对象而不指定具体类
组装过程
  • 建造者 把复杂对象的构建过程拆成步骤,同样过程可建不同表示
复制
  • 原型 以已有对象为模具,通过拷贝创建新对象
数量控制
  • 受控单例 单例 Singleton 保证一个类只有一个实例,并提供受控访问点 ← 全局实例到处被 import,测试难写

结构型

对象怎么组合与对接

接口对接
  • 适配器 把一个类的接口转换成客户期望的另一个接口 ← 两个接口对不上,又改不了其中一方
  • 外观模式 为子系统的一组接口提供统一的高层入口 ← 东西之间的关系乱
间接访问
  • 代理 为对象提供代理,控制对它的访问(缓存/校验/翻译/惰性加载) ← 外部会变化
动态叠加
  • 装饰器 动态地给对象叠加职责,而不改变其类 ← 加新功能必须改老代码
多维拆分
  • 桥接 抽象与实现分离,使两个维度可以独立变化
树形组合
  • 组合 把对象组成树表示部分-整体,统一单个与组合
共享减重
  • 享元 通过共享支撑大量细粒度对象

行为型

对象怎么协作 —— 职责如何在对象间分配与流动

算法替换
  • 策略模式 定义一族可互换的算法,运行时选择 ← 加新功能必须改老代码
  • 模板方法 固定算法骨架,变化步骤延迟到子类实现 ← 加新功能必须改老代码
请求对象化
  • 命令模式 把请求封装成对象:可参数化、排队、记录、撤销 ← 用户要求撤销 / 重做 ← 执行一半挂了,数据半新半旧
  • 责任链 多个对象都有机会处理请求,发送者与接收者解耦
通信解耦
  • 观察者 定义一对多依赖,主题变化时通知所有订阅者 ← 一变要通知多方,直接调用缠成网
  • 中介者 用中介对象集中封装多方交互,各方互不知晓 ← 一变要通知多方,直接调用缠成网
状态管理
  • 状态机 状态 State 对象随内部状态改变行为,看上去像改变了类 ← 外部会重复
  • Memento 在不破坏封装的前提下捕获并保存状态,以便恢复 ← 历史丢了,无法审计回放 ← 用户要求撤销 / 重做
遍历访问
  • 迭代器 顺序访问聚合元素而不暴露内部结构
  • 访问者 在不改元素类的前提下,为元素结构定义新操作
语法解释
  • 解释器 为简单语言定义文法表示并解释执行
